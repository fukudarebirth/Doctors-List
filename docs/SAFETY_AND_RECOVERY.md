# 承認付き追記と復旧

0.2.0はDry Runを初期状態とし、読み取り専用OAuthと書き込みOAuthを別ファイルで管理します。本番追記は候補・正本内容・書式・予定範囲・JST日付を含む承認対象に結び付けます。GUIの2つの確認欄と、その差分の `承認 操作ID先頭12文字` の入力が必要です。

## 保存処理

1. 全タブの値と、ユーザー入力値・数式・セル書式・入力規則・列幅・行高・シート構成を取得。取得の前後で値が変わった場合は停止。
2. 候補・除外・保留・A〜G差分を提示。ファイル選択変更、準備後15分経過、JST日付変更、正本変更で承認を失効。
3. 承認後に全タブを再取得して重複を再評価。承認時の値・書式と一致しなければ送信しない。
4. `operations/操作ID/backup.json` に承認対象と保存前モデルを保存し、再読み込みハッシュを確認。`journal.json` を送信前に保存。
5. ディスク保存後、直前の正本を再取得。新規範囲だけを単一の `spreadsheets.batchUpdate` で追記。自動リトライは0回。
6. 直前の最終データ行から書式・入力規則を継承。値は明示的な文字列として設定し、数式注入を防止。追加行の高さだけ20pxに設定。必要な場合のみ末尾のグリッド容量を増加。
7. 全タブを再取得。既存セル・書式・列幅・設定の不変、予定値・連続位置・行高・入力規則・行数を保存前モデルと予定変更から検証。実人数は未同定ならnullのまま。
8. 確認済み正本からだけマスターを更新して保存・再読み込みし、report.jsonを保存。最後にjournalをverifiedへ変更。元のマスターは保持。

Google Sheets APIは厳密な比較更新・排他を保証しません。最後の取得と送信の間に他者が編集すると競合し得ます。ローカルのOSロックも別PC・別の操作保存先・手動編集には効きません。**書き込み中は単一担当・単一PC・同じ設定と保存先に限定し、他の編集を停止してください。** API側の完全な排他制御を実装したものではありません。

## 対応範囲

- メインだけを人物シートとして使う現構成に対応。分類・統合など追加の人物シートがある場合、既存の反映手順を実装するまで停止します。
- 見本行または追記先の結合セル、見本行のCUSTOM_FORMULA/ONE_OF_RANGE入力規則、表示末尾より下の値・空表示の数式、見本となる既存人物行がない場合は停止します。
- 予定範囲の書式・入力規則を直前のデータ行から継承します。複雑な書式のAPI適用結果が予定と異なる場合は検証不一致として停止し、成功とは報告しません。
- バックアップは値・数式・書式等の比較モデルです。Googleファイル全体の履歴・コメント・画像等を復元するファイルコピーではありません。自動復元機能はありません。
- JSONの安全読み込み上限は20MiBです。超える場合は送信前のバックアップ段階で停止します。候補人数の上限として扱わず、実データ量に応じて保存方式を改修します。
- サンプル判定は予約ドメイン・synthetic指定を補助的に検知するものです。実在性を自動証明するものではありません。

## エラー後の操作

追記中のエラーでは同じ追記を繰り返しません。「保存状態を確認」は読み取り専用OAuthを使い、Googleへの再送を一切行いません。アプリ再起動後は該当する `operations/操作ID/journal.json` を選択します。

| 状態 | 対応 |
| --- | --- |
| 送信前の承認・正本・書式チェックで停止 | 最新差分を新しく準備し、再確認・再承認 |
| journalがnot_sent_changed | 送信直前の変更検出で未送信。古い操作は再使用せず新しい差分を準備 |
| 応答消失・保存結果不明 | 他の追記も停止。保存状態を読み取りで確認 |
| 全予定値と既存状態が一致 | 再追記せず検証・マスター保存・レポート生成を完了 |
| シート保存成功後にローカル保存失敗 | 保存先を復旧し「保存状態を確認」。再追記しない |
| 未保存らしい／一部保存／他編集と混在 | 自動再試行・自動削除・上書き復旧をしない。管理担当者がバックアップ・ジャーナル・現在のシート・変更履歴を確認 |
| verifiedの同じ操作を再実行 | ハッシュ確認済みの既存レポートを返す。新規送信なし |

成否不明のjournalは、現在行が空でも自動解除しません。タイムアウトしたリクエストが後から完了する可能性があるためです。管理担当者が送信の終了と実保存状態を確定した後に、記録を保持した手動復旧を行う必要があります。未解決のjournalやoperationsフォルダーを削除して再実行する操作は避けてください。

OAuth・取得エラー時は古い正本へ自動退避しません。未対応スキーマは原本を保持し、個人情報なしの構造を確認して対応します。バックアップを既存行へ自動上書きする機能はありません。

## CLI（画面を使う場合は不要）

すべての実データパスはリポジトリ外を指定します。

```text
python -m doctors_list prepare-append --config SETTINGS --candidates CANDIDATES --master MASTER --output PLAN
python -m doctors_list auth-write --config SETTINGS
python -m doctors_list apply-append --config SETTINGS --plan PLAN --approval "承認 表示された12文字" --single-writer
python -m doctors_list recover --config SETTINGS --operation-id 完全な64文字の操作ID
```

prepare-appendは読み取りだけを行います。PLAN内のpayload.reportに全候補・除外・保留理由とセルごとの差分があるため、必ず内容を確認してから承認します。apply-append後は、その操作フォルダー内のmaster-updated.jsonを次回以降のマスターとして選びます。CLIの標準出力には個人名・メールを出しません。
